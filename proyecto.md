## Descripción de la aplicación que vas a desarrollar

El proyecto consiste en desarrollar un sistema integral de administración de préstamos que permitirá gestionar clientes mediante datos generales, además de mantener su historial de préstamos y referencias.

Para la simulación de préstamos se podrán configurar frecuencias de pago semanales, quincenales o mensuales, así como diferentes esquemas de cálculo de intereses, incluyendo interés simple sobre capital original, saldo insoluto y cuota fija precalculada.

También contará con un generador de pagarés y documentos en PDF con los datos del cliente, condiciones del préstamo, intereses moratorios y tabla de amortización para su impresión y firma física.

El módulo de cobranza permitirá generar rutas y listas filtradas de clientes, consultar pagos pendientes y registrar manualmente abonos en efectivo o mediante transferencia SPEI, incluyendo pagos parciales, adelantados y destinados a intereses.

Además, tendrá un cotizador de préstamos para calcular rápidamente la cuota periódica, intereses, ganancia estimada, importe total y fecha tentativa de terminación a partir del monto, plazo y tasa.

Se incorporará un dashboard financiero con indicadores como dinero total prestado, capital recuperado y proyectado, intereses y utilidad generada e índice de morosidad, junto con un módulo de análisis y comparación de préstamos bancarios para evaluar tasas, CAT, cuotas, intereses y costos frente a otras alternativas de financiamiento. Finalmente, el sistema contará con historial y auditoría de operaciones para mantener la trazabilidad de los movimientos realizados por cada usuario.

Interesados de la aplicación: Personas con capital.

Usuarios que utilizaran la aplicación: Administrador, prestamistas, cobradores.

## 1. Dispositivos físicos para la ejecución de la aplicación

Para la operación de Credigest se emplearán distintos dispositivos según el rol de cada usuario. El Administrador y el Prestamista utilizarán una computadora de escritorio o laptop, ya que sus actividades requieren de una interfaz amplia para el manejo de información. El Cobrador empleará un dispositivo móvil, dado que su labor se desarrolla en campo, y lo usará también para fotografiar la identificación oficial (INE) y el comprobante de domicilio de los clientes. Se requerirá además una impresora en la oficina para imprimir el pagaré físico, y servidores en la nube para el almacenamiento de la información del sistema.

## Resumen:

* Computadora de escritorio o laptop: Administrador y Prestamista
* Dispositivo móvil (smartphone/tablet): Cobrador, para trabajo en campo
* Cámara del dispositivo móvil: captura de INE y comprobante de domicilio
* Impresora en oficina: impresión del pagaré legal
* Servidores en la nube: almacenamiento centralizado de la información

## 2. Entorno donde se ejecutará la aplicación

Credigest operará bajo una arquitectura cliente-servidor. El Administrador y el Prestamista accederán al sistema mediante una aplicación web, mientras que el Cobrador utilizará una versión adaptada para dispositivos móviles. Ambas interfaces se conectarán a un servidor de aplicación alojado en la nube, donde se ejecutan los cálculos de intereses, la tabla de amortización y la generación del pagaré en PDF. Dicho servidor se comunica con un servidor de base de datos, encargado de almacenar clientes, préstamos, pagos y bitácoras de auditoría.

Resumen:

* Aplicación web: Administrador y Prestamista
* Aplicación móvil: Cobrador
* Servidor de aplicación en la nube: procesamiento de cálculos y lógica de negocio
* Servidor de base de datos: almacenamiento de clientes, préstamos, pagos y auditoría

## 3. Comunicaciones requeridas para la ejecución de la aplicación

Para el funcionamiento del sistema es indispensable la conexión a Internet, ya sea por WiFi en la oficina o datos móviles durante la ruta de cobranza. Cada acción del usuario, como el registro de un pago, se envía al servidor mediante solicitudes HTTPS, protocolo que garantiza la protección de la información sensible del cliente. De forma interna, el servidor se comunica con la base de datos para almacenar y consultar información. El sistema también emite notificaciones automáticas, como credenciales de acceso o comprobantes de pago por correo o WhatsApp, y genera los documentos PDF del pagaré a solicitud del usuario.

Resumen:

* Conexión a Internet (WiFi o datos móviles): indispensable para el funcionamiento
* Comunicación aplicación-servidor: mediante HTTPS
* Cifrado HTTPS: protección de datos sensibles del cliente
* Notificaciones automáticas: correo electrónico y WhatsApp
* Generación de documentos PDF: solicitada al servidor y devuelta lista para impresión

## Registro Manual de Abono y Comprobante

[Imagen: Diagrama de actividad para el Cobrador. Muestra el flujo de llegar al domicilio del cliente, buscar cliente en la lista de cobro, consultar cuota pendiente. Si el método de pago es efectivo, recibe pago; si es SPEI, solicita referencia o comprobante. Ingresa cantidad recibida e indica método de pago. Dependiendo del tipo de pago (pago parcial, abono completo, pago adelantado, intereses moratorios), registra el abono. Presiona "Registrar Pago". El sistema recalcula saldo insoluto, confirma transacción, emite recibo digital, actualiza estado del cobro y actualiza información del sistema global. Finalmente, el Cobrador entrega o envía comprobante.]
